## ۳. معماری (از صحبت با ذاکری)
- این ریپو (`zakeriuae/car-rental-hub`) = **داشبورد / هسته‌ی بیزنس** درایوکس: CRM، لیدها، واتس‌اپ/تلگرام، فلیت، تقویم، رزروها.
- **اپ مشتری مستقیم به همان دیتابیس Supabase وصل می‌شود** — بدون API واسطه و بدون عبور از پنل. پنل هم مستقیم وصل است.
- ریپو/پروژه‌ی Vercel جدا برای اپ مشکلی ندارد (ذاکری در نهایت قبول کرد)؛ مهم فقط اتصال مستقیم به دیتابیس است.
- دامنه‌ها:
  - `drivex.ae` → سایت فعلی. **دست نمی‌زنیم** (مقاله و سئو دارد).
  - `admin.drivex` (یا `panel.drivex`) → همین داشبورد. الان فقط روی Vercel بالاست و دامنه ندارد.
  - `app.drivex` → اپ مشتری.
  - وصل کردن دامنه‌ها با ذاکری.
- ابزار: کار با اکانت Claude ذاکری (پلن معمولی؛ اگر ظرفیت کم آمد بعداً ارتقا).
- بک‌اند قابل استفاده‌ی مجدد از پروژه‌های دیگر: جدول‌های اجاره‌ی **آرسام** (RLS آن `USING (true)` است و باید بازنویسی شود)، OTP تلفن از **cafoo** (`lib/auth/phone-otp.ts`)، پرداخت با **Ziina** (لینک پرداخت).

## ۵. خلاصه‌ی گفتگوی حسین و ذاکری
- ذاکری: کامیار وسط کار حرفش را عوض می‌کند؛ فیگمای حسین را ولش کن. UI را فقط در پی‌وی بفرست.
- ذاکری پرامپت طراحی را می‌دهد؛ حسین بقیه‌ی صفحه‌ها را با آن بزند و هم‌زمان شروع کند.
- ذاکری: دیزاین‌ها را که بزنی، APIها همه از سرور است و به دیتا وصل می‌شود. پیشنهاد اول ذاکری: روی همان پروژه‌ی داشبورد درایوکس، یک بخش اپ اضافه شود و مستقیم از دیتابیس بخواند.
- حسین: داشبورد برای فالوآپ و واتس‌اپ است؟ ذاکری: نه، کل هسته‌ی بیزنس است (فلیت منیجر، تقویم، جدول زمانی)، مثل پروژه‌ی فرش‌فروشی.
- بحث یک پروژه یا دو پروژه: حسین گفت به‌خاطر دیپلوی جدا بهتر است؛ ذاکری گفت با ساب‌دامین می‌شود یک پروژه را به چند دامنه داد، ولی در نهایت گفت «برو یه ریپوی دیگه اصلاً؛ مهم اینه مستقیم از دیتابیس بخونه».
- `drivex.ae` دست نخورد؛ داشبورد → `admin.drivex`، اپ → `app.drivex`.
- داشبورد فعلاً فقط روی Vercel است، چون کامیار از آن استفاده نمی‌کرد.
- حسین پرسید Supabase را دیدی؟ ذاکری: نه، به من ندادی. حسین: می‌دهم.
